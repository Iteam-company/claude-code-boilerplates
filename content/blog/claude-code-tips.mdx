This boilerplate ships with Claude Code configuration out of the box: a detailed `CLAUDE.md`, a library of project-specific skills, and hooks that run automatically as you work. Here is how to use them effectively.

## What Is Already Configured

When you open this project in Claude Code, it reads `CLAUDE.md` and loads the full project context — conventions, file structure, naming rules, anti-patterns, and architecture decisions. You do not need to re-explain the stack every session.

On top of that, the project includes **skills** — reusable prompt templates for common tasks:

| Skill               | What It Does                                           |
| ------------------- | ------------------------------------------------------ |
| `drizzle-module`    | Scaffolds all 7 module files from schema to service    |
| `nextjs-api-route`  | Creates a thin API route following project conventions |
| `swr-hooks`         | Generates a typed SWR hook for any endpoint            |
| `auth-patterns`     | Explains and applies JWT auth patterns                 |
| `cloudinary-upload` | Wires up image upload end-to-end                       |
| `nextjs-mdx-blog`   | Sets up the MDX blog (file-based or DB-based)          |
| `drizzle-migrate`   | Runs generate + migrate after schema changes           |
| `ui-patterns`       | Applies Shadcn + Tailwind theming conventions          |

## How to Trigger a Skill

Type the slash command in the Claude Code prompt:

```
/drizzle-module
```

Claude Code will run the skill and ask you for the module name and fields. It then generates the full module — schema, relations, types, validation, repo, service, and index — all following the project's conventions.

## Effective Prompting Patterns

### Be specific about the entity

Instead of:

> Add a products feature

Write:

> Add a `product` module with fields: `name` (string), `price` (integer, cents), `description` (text, nullable), `imageUrl` (text, nullable), `authorId` (FK to users)

The more precise your field list, the less back-and-forth is needed.

### Reference the skill directly

If you want Claude Code to scaffold something, name the skill:

> Use the drizzle-module skill to create a `category` module with `name` and `slug` fields.

This ensures Claude Code loads the correct context before generating code.

### Ask for one layer at a time

For complex features, break the request into layers:

1. First: `Add the category schema and run migrations`
2. Then: `Add the repo and service for categories`
3. Then: `Add the API route for GET /api/categories`
4. Then: `Add a useCategoreis SWR hook`

This keeps each output focused and reviewable.

## Useful One-Liners

**Generate and apply a migration after a schema change:**

```
/drizzle-migrate
```

**Add a new Shadcn component:**

```
npx shadcn@latest add <component-name>
```

**Type-check without building:**

```
npx tsc --noEmit
```

**Inspect your database visually:**

```
npm run db:studio
```

## Reading the CLAUDE.md

The `CLAUDE.md` file is the single source of truth for project conventions. Whenever you are unsure about where to put something, read it. Claude Code reads it automatically, but you can too — it is written to be human-readable.

Key sections to know:

- **Anti-Patterns** — explicit list of things not to do
- **Module structure** — the 7-file chain and what belongs in each file
- **Auth** — how JWT tokens flow from login through `getUserFromRequest`
- **Error Handling** — `HttpError` + `handleError` pattern

## When to Use `"use client"`

A common mistake when prompting Claude Code is not being clear about whether a component is interactive. If you need event handlers, `useState`, `useEffect`, or browser APIs, say so explicitly:

> Create a `CommentForm` **client component** that submits a comment via the `useCreateComment` mutation hook.

Without "client component", Claude Code defaults to a Server Component, which cannot use hooks.

## Keeping Context Fresh

Claude Code's context window has limits. In long sessions:

- Start a new session for a new module or feature
- Reference specific file paths when asking about existing code (`modules/post/post.service.ts`)
- Use `/compact` if the session gets slow — it summarizes earlier context

> Claude Code works best when you treat it as a pair programmer who has read your CLAUDE.md but needs you to drive the conversation. Give precise inputs, review every output, and iterate.

TypeScript's value comes from the discipline of using it well. Here are the patterns that matter most in a real codebase.

## Avoid `any` — Use `unknown`

`any` disables type checking. `unknown` forces you to narrow the type before using it, which is always what you actually want:

```ts
function parseInput(value: unknown): string {
  if (typeof value === 'string') return value;
  if (typeof value === 'number') return String(value);
  throw new Error('Unsupported input type');
}
```

## Use `type` vs `interface` Deliberately

- Use `interface` for object shapes that may be extended or implemented
- Use `type` for unions, intersections, primitives, and mapped types

```ts
interface UserProfile {
  id: string;
  email: string;
  role: 'admin' | 'user';
}

type ApiResponse<T> = { data: T; error: null } | { data: null; error: string };
```

## Infer Types from Zod Schemas

Define your validation schema once and derive TypeScript types from it. This keeps runtime validation and compile-time types in sync:

```ts
import { z } from 'zod';

const LoginSchema = z.object({
  email: z.string().email(),
  password: z.string().min(8),
});

type LoginData = z.infer<typeof LoginSchema>;
// { email: string; password: string }
```

## Discriminated Unions for State

Model loading, error, and success states as a discriminated union. TypeScript narrows the type based on the `status` field:

```ts
type RequestState<T> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; message: string };

function render(state: RequestState<User>) {
  if (state.status === 'success') {
    return state.data.email; // TypeScript knows data exists here
  }
}
```

## Utility Types

TypeScript ships with powerful utility types. Learn these before reaching for a library:

| Utility         | Purpose                        |
| --------------- | ------------------------------ |
| `Partial<T>`    | All properties optional        |
| `Required<T>`   | All properties required        |
| `Omit<T, K>`    | Remove keys from a type        |
| `Pick<T, K>`    | Keep only specified keys       |
| `Readonly<T>`   | Prevent mutation               |
| `ReturnType<T>` | Infer a function's return type |

## Strict Mode

Always enable `"strict": true` in `tsconfig.json`. It enables:

- `strictNullChecks` — `null` and `undefined` are not assignable by default
- `noImplicitAny` — variables must have a type
- `strictFunctionTypes` — stricter checking of function types

A codebase with strict mode off is a codebase with hidden runtime errors.
